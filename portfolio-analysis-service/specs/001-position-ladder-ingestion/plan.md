# Implementation Plan: Position Ladder Ingestion

**Branch**: `001-position-ladder-ingestion` | **Date**: 2026-07-06 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/001-position-ladder-ingestion/spec.md`

## Summary

Build a FastAPI web service (`portfolio-analysis-service`) that accepts XLSX sub-account
ledger files produced by the `create_subaccount_ledger` pipeline, validates their schema,
expands them into a daily position ladder (Mon–Fri, earliest activity date through T-2
business days), and persists the result as an XLSX file for later retrieval. Idempotency
is enforced via SHA-256 checksum; a changed-file submission returns 409 (merge not
supported). The service mirrors the technology conventions of `market-data-web-service`.

## Technical Context

**Language/Version**: Python 3.11
**Primary Dependencies**: FastAPI 0.115, uvicorn, pandas, openpyxl, structlog, pydantic ≥2.0
**Storage**: Local filesystem — one directory per account under `data/`; `ladder.xlsx` +
`meta.json` per account
**Testing**: pytest 8, pytest-bdd 7; `.feature` files in `tests/features/`,
step implementations in `tests/steps/`
**Target Platform**: Local development machine / localhost server (no cloud deployment)
**Project Type**: Web service (REST API)
**Performance Goals**: New ingestion ≤10 s for 5,000 input rows; idempotent re-submit ≤1 s;
validation rejection ≤1 s
**Constraints**: No authentication; no external database; no public holiday calendar (weekends
only excluded from business day calculation); merge path returns 409, not implemented
**Scale/Scope**: Single user / local instance; no concurrent-write safety required in v1
