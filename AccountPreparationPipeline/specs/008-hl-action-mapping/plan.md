# Implementation Plan: HL Action Mapping — Card Web, FPC, Commission

**Branch**: `008-hl-action-mapping` | **Date**: 2026-06-11 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `specs/008-hl-action-mapping/spec.md`

## Summary

Add three missing reference→action mappings to the HL fragment parser so that "Card Web" and "FPC" (case-insensitive) map to `deposit`, and "Commission" (case-insensitive) maps to `income`. All three currently raise a `ValueError` (→ `ParseError`), dropping rows from the consolidated journal. The change is a two-file extension: new constants in `constants.py` and new branches in `_map_action()` in `hl.py`. Simultaneously, the existing hardcoded income reference strings (`"INTEREST"`, `"RDP CR"`) are extracted to a named constant, resolving a latent constitution violation.

## Implementation Design

### constants.py additions

```text
HL_DEPOSIT_REFERENCE_ALIASES: frozenset[str] = frozenset({"CARD WEB", "FPC"})
  Stored as uppercase; compared via ref.upper() in HL_DEPOSIT_REFERENCE_ALIASES

HL_INCOME_REFERENCES: frozenset[str] = frozenset({"INTEREST", "RDP CR", "COMMISSION"})
  Consolidates existing "INTEREST"/"RDP CR" magic strings + new "COMMISSION"
  Compared via ref.upper() in HL_INCOME_REFERENCES
```

### _map_action() change (hl.py)

Existing deposit branch:
```python
if ref in HL_DEPOSIT_REFERENCES or ref.upper().startswith("BACS"):
    return ActionType.DEPOSIT
```
Extended to:
```python
if ref in HL_DEPOSIT_REFERENCES or ref.upper().startswith("BACS") \
        or ref.upper() in HL_DEPOSIT_REFERENCE_ALIASES:
    return ActionType.DEPOSIT
```

Existing income branch (magic strings):
```python
if ref.upper() in ("INTEREST", "RDP CR"):
    return ActionType.INCOME
```
Replaced with:
```python
if ref.upper() in HL_INCOME_REFERENCES:
    return ActionType.INCOME
```

Order of branches is preserved — new deposit aliases evaluated after existing `HL_DEPOSIT_REFERENCES` check.
