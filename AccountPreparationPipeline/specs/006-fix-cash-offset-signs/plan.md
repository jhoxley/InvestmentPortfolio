# Implementation Plan: Fix Cash Offset Signs

**Branch**: `006-fix-cash-offset-signs` | **Date**: 2026-06-10 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `specs/006-fix-cash-offset-signs/spec.md`

## Summary

The `OffsetGenerator._make_offset` method in `src/modes/consolidate_journals/offset_generator.py`
uses `value = -event.value`, which inverts the sign of every Cash offset row. Because HL CSV
exports store buy values as negative (cash outflow) and sell values as positive (cash inflow),
this negation reverses the correct direction: buy offsets become positive (cash appears to
increase) and sell offsets become negative (cash appears to decrease). The fix replaces
`-event.value` with `event.value` (one character change) so the offset mirrors the trade's value
directly. Test fixtures in `test_offset_generator.py` and the CSV test file `valid_hl_simple.csv`
must also be corrected because they assumed the wrong sign convention.

### Journal store update-in-place (FR-005)

`src/modes/consolidate_journals/journal_store.py` needs a new method to support correcting
stale offset rows. The existing `merge()` inserts new rows but skips any row whose reference
already exists — it has no update path.

Proposed new method `rectify_offsets(trades: pd.DataFrame) -> int`:
- For each buy/sell row in `trades`, compute the expected offset reference (`ref + "-offset"`)
- Find any existing offset row with that reference
- If found and `offset.value != trade.value` (wrong sign): update `value` and `quantity` in place
- Return count of rows corrected

`consolidator.py` calls:
1. `store.missing_offset_trades()` — generates offsets for trades with no offset row at all
2. *(new)* `store.rectify_offsets(all_trades)` — corrects value/quantity on offset rows that
   exist but carry the wrong sign

New tests in `tests/unit/consolidate_journals/test_journal_store.py`:
- `test_rectify_offsets_corrects_wrong_sign_buy` — buy offset has positive value → rectify → negative
- `test_rectify_offsets_corrects_wrong_sign_sell` — sell offset has negative value → rectify → positive
- `test_rectify_offsets_no_change_when_correct` — returns 0 when all offsets already correct
- `test_rectify_offsets_does_not_touch_non_offset_rows` — non-offset rows unaffected

### Engine test semantic correction
