# Implementation Plan: Income Dividend Action Mappings

**Branch**: `009-income-dividend-mappings` | **Date**: 2026-06-18 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `specs/009-income-dividend-mappings/spec.md`

## Summary

Add four missing reference→action mappings to the HL fragment parser so that `"ST DIV"`, `"OVR CR"`, `"UTC CR"`, and `"LOYALTYU"` all map to a new `ActionType.DIVIDEND`. For these events the sub-account is derived from the description field by stripping a reference-specific suffix — three are static strings and one (`LOYALTYU`) uses a regex to strip the dynamic month-year component. The change spans three source files (`schema.py`, `constants.py`, `hl.py`) and adds a pure helper function `_strip_dividend_suffix()`. Once complete, running `consolidate_journals` against the full HL ISA Income Account fragment history produces zero dropped rows.

## Implementation Design

### schema.py addition

```python
class ActionType(StrEnum):
    BUY = "buy"
    SELL = "sell"
    DEPOSIT = "deposit"
    INCOME = "income"
    FEE = "fee"
    WITHDRAWAL = "withdrawal"
    TRADING = "trading"
    DIVIDEND = "dividend"          # ← new
```

`DIVIDEND` must NOT be added to `CASH_ACTION_TYPES` — dividend sub-accounts carry the holding name, not `"Cash"`.

### constants.py additions

```python
# Final state shown; built incrementally across US1–US4 per tasks.md.
HL_DIVIDEND_REFERENCES: frozenset[str] = frozenset({"ST DIV", "OVR CR", "UTC CR", "LOYALTYU"})

# Suffix tuples are tried in order; first match wins.
HL_DIVIDEND_SUFFIX_MAP: dict[str, tuple[str, ...]] = {
    "ST DIV":    (" Dividend Payment",),
    "OVR CR":    (" Overseas Dividend Payment",),
    "UTC CR":    (" Eql - UT Cash Payment", " UT Cash Payment"),
}

RE_LOYALTYU_SUFFIX: re.Pattern[str] = re.compile(r" \d{2} \d{2} Gross Loyalty$")
```

`HL_DIVIDEND_REFERENCES` stored as uppercase; comparison via `ref.upper()` in `_map_action()`.
`HL_DIVIDEND_SUFFIX_MAP` keyed by uppercase reference, consistent with how the map is accessed.

### New helper: _strip_dividend_suffix() (hl.py)

```python
def _strip_dividend_suffix(reference: str, description: str) -> str:
    ref_upper = reference.strip().upper()
    if ref_upper == "LOYALTYU":
        if not RE_LOYALTYU_SUFFIX.search(description):
            raise ValueError(
                f"LOYALTYU description does not match expected"
                f" '\\d{{2}} \\d{{2}} Gross Loyalty' pattern: {description!r}"
            )
        result = RE_LOYALTYU_SUFFIX.sub("", description).strip()
    else:
        result = description
        for suffix in HL_DIVIDEND_SUFFIX_MAP.get(ref_upper, ()):
            if result.endswith(suffix):
                result = result[: -len(suffix)].rstrip()
                break
    return result or description or reference
```

**LOYALTYU non-match → parse error (FR-008A)**: If `RE_LOYALTYU_SUFFIX` does not match the description, `ValueError` is raised. The caller (`_parse_row`) wraps this in `_RowParseError`, so the row is dropped and the error is included in the consolidation summary. The `result or description or reference` fallback applies only when the suffix IS found but stripping yields an empty string (e.g., fund name was absent before the suffix).
